# 개발 로드맵

## M0 — 저장소와 계약

- [x] 프로젝트명, 범위, 구성, API 계약
- [x] Java CLI 소스 초안
- [x] Mac JDK 17+에서 미리보기와 클립보드 실행 확인 (CRLF→LF 정규화, Tab 표시, 한글 거절 — 2026-10-08)

## M1 — USB HID 첫 성공

- [x] 칩, Flash/PSRAM 용량, Native USB 배선 확인 (ESP32-S3, 4MB/2MB, Native USB 직결) — BOOT=GPIO0 런타임 입력 동작 확인, LED 핀 미확인
- [x] Arduino-ESP32 HID 펌웨어 빌드, 사용한 정확한 버전 기록 (esp32 3.3.2, 컴파일·업로드·키보드 인식 확인)
- [x] 키보드 인식 후 버튼을 누르면 Hello World 입력 (`firmware/clipkey_hello`, 2026-10-08 실물 확인)
- [x] 대문자, 숫자, 모든 ASCII 기호와 반복 문자 검증 (M2.2 타이핑 테스트로 확인, 2026-10-08)

완료 기준: 대상 PC의 텍스트 편집기에 한 번의 버튼 조작으로 정확하게 입력되고, 재부팅 시 자동 입력되지 않는다.

## M2 — 무선 작업 수신

- [x] Wi-Fi 다중 SSID 연결, mDNS `clipkey.local`(IPv4/IPv6), 토큰 인증 — M2.1 실물 검증 완료
- [x] 크기/문자/옵션 검증 (M2.2, curl 실측)
- [x] v0.1 작업 등록·상태·취소 엔드포인트 (M2.2)
- [x] 대기 60초 만료, 버튼 승인, press/release — 80자(Tab·LF·기호·추가 Enter 포함) 정확 입력 실측
- [x] 버튼 중단 실측 (2,819자 작업을 701자에서 중단, 화면 출력과 일치, 키 잔류 없음)
- [x] 중복 ID 방지(실측). USB 분리는 보드가 대상 PC USB 전원을 쓰므로 재부팅 = 작업 소실: 송신기는 상태 조회 404 를 '알 수 없음'으로 다룬다. Wi-Fi 단절은 자동 재접속(코드), 실측 생략

완료 기준: 정상 요청은 승인 전까지 입력되지 않고, 인증 실패/한글/초과 길이 요청은 한 글자도 입력하지 않는다.

## M3 — 클립보드 연결

- [x] Java CLI → 실제 펌웨어 연동 (`.app` 번들로 202 등록 → 버튼 → 입력 완료 확인)
- [x] Tab, 여러 줄, Enter 옵션 검증 (CRLF 는 송신기 정규화, 단위 테스트 수준)
- [x] 4,095자@20ms, 2,549자@10ms, 329자@100ms 누락 없음 (2026-10-08 TextEdit 대조). 50ms 는 10~100 사이라 생략
- [x] 응답 손실 시 상태 조회 및 재입력 방지 확인 (동일 ID 재전송 202, 재입력 없음 — curl 실측)

## M4 — 일상 사용

- [x] Java Swing UI: 장치 주소, 미리보기, 보내기, 진행/취소 (M4.1, 2026-10-08 전송→버튼→완료 실측)
- [x] 물리 버튼/LED UX (M4.3: 상태별 RGB·파란 LED, 2026-10-08 실측) — 케이스는 별도
- [ ] 캡티브 포털로 Wi-Fi/토큰 런타임 설정 (재빌드 없이 새 장소 추가)
- [ ] 토큰 교체와 설정 초기화
- [ ] 버튼 없는 자동 입력(autoStart, 2초 취소 창) — M4.4a 구현, 실측 대기

후속: BLE, OTA, 장문 청크 전송. 보드 실측 전에 구현 기간이나 최종 속도를 확정하지 않는다.
