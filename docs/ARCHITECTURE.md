# 아키텍처

## 구성 요소

| 구성 | 역할 | 기술 |
|---|---|---|
| 송신기 | 클립보드 읽기, 정규화, ASCII 검증, 미리보기, 요청 전송 | Java 17 AWT / HttpClient |
| 통신 | 동일 Wi-Fi의 보드로 작업 등록 | HTTP, Bearer token |
| 보드 | 요청 검증, 작업 보관, 버튼 승인, HID 출력 | ESP32-S3 / Arduino-ESP32 / TinyUSB |
| 대상 PC | 현재 포커스된 앱에서 키 입력 수신 | USB HID 키보드 |

## 처리 흐름

수신 전체를 검증한 다음 4KB의 제한 버퍼에 보관한다. v0.1은 스트리밍 입력 대신 완전한 작업 단위로 처리한다. 한글이나 잘못된 제어문자 때문에 앞부분만 입력되는 일을 방지하기 위함이다.

작업 상태: WAITING → TYPING → COMPLETED. 대기 만료 또는 버튼 중단은 CANCELLED, USB 연결 해제 등은 FAILED. 재부팅 시 작업을 복구하거나 재실행하지 않는다.

HTTP 핸들러는 작업을 등록하고 즉시 응답한다. HID 출력은 루프 또는 별도 태스크가 처리한다. 각 문자에서 press/release를 수행하며, 완료·취소·오류 때 모든 키를 해제한다. 버튼은 디바운싱과 누름 에지 검출을 적용한다. 승인에 쓴 버튼을 계속 누르고 있어도 즉시 취소로 해석하지 않는다.

## 입력 정확성

- ASCII 0x20~0x7E와 LF/Tab만 지원. Backspace 및 임의 단축키는 v0.1에서 제외.
- 클라이언트와 펌웨어가 각각 길이와 문자를 검증한다.
- 대상 PC의 IME가 한글이면 영문 HID 코드도 한글로 입력될 수 있다.
- Caps Lock과 키보드 배열은 결과에 영향을 준다. 대상 PC에서 영문/US 배열을 준비한다.
- Tab은 포커스를 이동할 수 있고 LF는 터미널 명령을 실행할 수 있다. 여러 줄 내용은 전송 전에 확인한다.
- 편집기의 자동 들여쓰기 때문에 코드의 공백이 달라질 수 있다. 일반 텍스트 편집기에서 우선 검증한다.
- macOS TextEdit 등은 `'`/`"`를 `’`/`”`로 자동 치환한다(스마트 인용부호). 보드는 ASCII 키코드를 보내므로 코드 편집기나 치환을 끈 앱에서는 그대로 입력된다(실측).
- 속도는 HID 전송과 대상 앱의 처리에 따라 조정하며, 타이핑 결과를 보드가 읽어서 확인할 수는 없다.

## 연결과 설정

v0.1은 기존 Wi-Fi 접속(STA)이며, 여러 SSID를 저장해 두고 부팅·재접속 시 신호가 가장 좋은 곳에 붙는다(집/회사/폰 핫스팟). 보드는 mDNS로 `clipkey.local`에 응답하므로 송신기는 IP를 몰라도 된다. SSID/비밀번호/토큰은 `secrets.h`(비공개, Git 제외)로 관리하며, 재빌드 없이 바꾸는 캡티브 포털 설정은 M4에서 다룬다. 토큰과 원문 텍스트를 로그에 남기지 않는다.

HTTP는 암호화되지 않는다. 초기 개발은 신뢰하는 로컬 네트워크에서 진행한다. 외부 노출 없이 토큰 인증과 물리 승인으로 접근을 제한하며 HTTPS/BLE bonding은 후속 검토한다.
